## Implementation

The `global_variance.py` changes consist of importing `json`, narrowed module/_same docstrings, `_require_strict_json`, and a final export check in each of its nine serializable dataclasses. AST inspection confirms that all nine export checks are the last statement of `__post_init__`. `TwoPhaseSmoothedMoments` has no serialization method, so its absence from this set is correct. `json.dumps(export, allow_nan=False)` is caught for `TypeError` and `ValueError` and re-raised as a dedicated `GlobalVarianceContractError` with a precise field/context message. The promise applies to the actual export, including only the nested fields that the export includes; it does not impose strict JSON on hidden density G/identity_tolerance fields.

The 1G-B diff changes exactly two `__post_init__` methods. No factory, equation, runtime tolerance, output key, status constant, normalization or default changes. The new LCDM relative-change expression and each new anchored ratio/offset expression repeat their respective factory operations in the same order. `_EARLY_SPECTRUM_COMPARED` is the unchanged tuple used by the factory and the record. Therefore the same-environment native-float factory outputs have matching exact expressions, rather than unrelated numerical implementations with a spurious zero tolerance. This is not a Windows validation claim.

Other direct-construction limitations are expressly disclosed in the 1G-B successor: factory-only compatibility checks are not repeated, scalars are not universally normalized, and the LCDM truncation envelope is finite/domain/budget-checked but not recomputed from the spectrum. A zero truncation diagnostic within its declared budget remains accepted; it must not be advertised as a spectrum-recomputed result.
